# Finance Wallet CLI

Backend-приложение для управления личными финансами с интерактивным CLI. Учебный проект по ООП: несколько пользователей, кошельки, доходы и расходы, категории, бюджеты, отчёты, уведомления, сохранение в JSON, переводы между пользователями, тесты и CI.

## Возможности

- Регистрация и авторизация по логину и паролю; поддержка нескольких пользователей.
- Пароли хранятся только в виде PBKDF2-HMAC-SHA256 хеша с индивидуальной солью.
- Кошелёк привязан к авторизованному пользователю и хранит баланс, операции, категории и бюджеты.
- Доходы и расходы с категориями, комментариями и временем операции.
- Категории доходов и расходов: создание, переименование, удаление, просмотр.
- Бюджеты по категориям расходов: установка, изменение, удаление, остаток и процент использования.
- Отчёты: общая сумма доходов/расходов, разбивка по категориям, состояние бюджетов.
- Фильтры отчётов по нескольким категориям, типу операций и периоду дат.
- Уведомления при 80% бюджета, исчерпании и превышении лимита, превышении расходов над доходами, нулевом и отрицательном балансе.
- Переводы между кошельками по логину: расход у отправителя, доход у получателя.
- Автосохранение после каждой операции, сохранение при `logout` и при выходе; загрузка кошелька при `login`.
- Экспорт и импорт снимка кошелька в JSON с полной валидацией перед заменой данных.
- Форматированные таблицы, справка `help`, подсказки при опечатках и понятные сообщения об ошибках.

## Требования

- JDK 17+
- Maven 3.8+

Внешние библиотеки подключаются Maven автоматически:

- Jackson Databind и Jackson JSR-310 — JSON и даты;
- JUnit 5 — тесты;
- Checkstyle и JaCoCo — проверка стиля и покрытие в фазе `verify`.

## Быстрый старт

```bash
mvn clean package
java -jar target/finance-wallet-1.0.0-all.jar
```

Папка данных по умолчанию — `./data`. Другую папку можно указать так:

```bash
java -jar target/finance-wallet-1.0.0-all.jar --data-dir "C:\finance-data"
```

В Windows-терминале для корректного отображения кириллицы при необходимости выполните `chcp 65001`.

При первом запуске зарегистрируйте пользователя и войдите:

```text
> register alice secret123
OK: пользователь «alice» зарегистрирован.
> login alice secret123
OK: добро пожаловать, alice!
> demo
```

Команда `demo` заполняет **пустой** кошелёк примером из задания. Дальше:

```text
> report all
```

Выход:

```text
> exit
OK: данные кошелька «alice» сохранены. Баланс: 54,700.00.
До свидания.
```

Данные сохраняются и при завершении ввода (`Ctrl+D` / EOF), и после каждой изменяющей операции.

## Команды

Команды и аргументы разделяются пробелами. Аргументы с пробелами заключайте в кавычки. Суммы — положительные числа; поддерживаются `1500`, `1500.50`, `1500,50`.

| Команда | Назначение |
|---|---|
| `help [команда]` | Список команд или подробная справка по одной команде |
| `register <логин> <пароль>` | Регистрация. Логин: 3–30 букв/цифр/`_`/`-`, пароль: от 6 символов |
| `login <логин> <пароль>` | Вход и загрузка кошелька из файла |
| `logout` | Сохранение кошелька и завершение сессии |
| `whoami` | Текущий пользователь и состояние кошелька |
| `income <сумма> <категория> [--note <текст>]` | Добавить доход; категория создаётся автоматически |
| `expense <сумма> <категория> [--note <текст>]` | Добавить расход; категория создаётся автоматически |
| `transfer <логин> <сумма> [--note <текст>]` | Перевод другому пользователю |
| `category add <название> [--type expense\|income]` | Создать категорию (по умолчанию расходная) |
| `category list` | Категории, число операций и бюджеты |
| `category rename <старое> <новое>` | Переименовать категорию во всех операциях и бюджете |
| `category delete <название>` | Удалить категорию без операций и бюджета |
| `budget set <категория> <лимит>` | Установить/изменить бюджет расходной категории |
| `budget list` | Лимит, потрачено, остаток, процент и статус |
| `budget remove <категория>` | Удалить бюджет |
| `report` или `report summary` | Общий доход, расходы, баланс, число операций |
| `report categories` | Доходы и расходы по категориям |
| `report budgets` | Таблица бюджетов |
| `report all` | Сводка + категории + бюджеты |
| `report ... --type all\|income\|expense` | Фильтр по типу операций |
| `report ... --categories "Еда,Такси"` | Несколько выбранных категорий |
| `report ... --from YYYY-MM-DD --to YYYY-MM-DD` | Период (границы включительно, локальная зона) |
| `export <файл.json>` | Экспорт снимка кошелька |
| `import <файл.json> [--force]` | Импорт снимка; `--force` нужен для замены непустого кошелька |
| `save` | Принудительно сохранить кошелёк |
| `demo` | Загрузить пример из задания в пустой кошелёк |
| `exit` / `quit` | Сохранить данные и выйти |

`?` — псевдоним `help`.

### Сценарий из задания вручную

```text
register alice secret123
login alice secret123
expense 300 Еда
expense 500 Еда
expense 3000 Развлечения
expense 3000 "Коммунальные услуги"
expense 1500 Такси
income 20000 Зарплата
income 40000 Зарплата
income 3000 Бонус
budget set Еда 4000
budget set Развлечения 3000
budget set "Коммунальные услуги" 2500
report all
exit
```

Ожидаемые ключевые значения: доход `63,000.00`, расходы `8,300.00`, баланс `54,700.00`; остатки бюджетов: Еда `3,200.00`, Коммунальные услуги `-500.00`, Развлечения `0.00`.

### Переводы

Пользователи должны быть зарегистрированы:

```text
register alice secret123
register bob secret123
login alice secret123
income 1000 Зарплата
transfer bob 300 --note "возврат долга"
logout
login bob secret123
report
```

У Алисы появится расход `Переводы (исходящие)`, у Боба — доход `Переводы (входящие)`. Перевод возможен только при достаточном балансе отправителя; перевод самому себе запрещён. Оба кошелька сохраняются сразу, поэтому получателю не нужно быть онлайн.

### Экспорт и импорт

```text
export backup.json
import backup.json --force
```

Импорт:

- проверяет JSON, версию схемы, владельца, ссылки операций на категории и корректность сумм;
- не позволяет импортировать снимок чужого пользователя;
- не заменяет непустой кошелёк без `--force`;
- при ошибке оставляет текущий кошелёк без изменений.

## Уведомления

После расхода и при входе приложение сообщает:

- `[!]` при достижении 80% лимита — один раз при пересечении порога;
- `[!]` при точном исчерпании лимита и нулевом балансе;
- `[!!]` при превышении лимита, отрицательном балансе и превышении расходов над доходами;
- `[i]` когда баланс снова становится неотрицательным.

Пороговые уведомления не повторяются после каждой следующей операции: сравнивается состояние «до» и «после».

## Хранение данных

```text
data/
├── users.json                      # пользователи: логин, соль, хеш пароля
└── wallets/
    └── <base64url(логин)>.json     # снимок кошелька
```

- Все рабочие данные находятся в памяти приложения; JSON — слой долговременного хранения.
- Файлы пишутся атомарно через временный файл, чтобы сбой не оставил половину JSON.
- `users.json` загружается при старте, кошелёк — при `login`.
- Снимок кошелька содержит версию схемы, владельца, категории, все операции и бюджеты.
- Пароли не сохраняются в открытом виде.
- Папка `data/` исключена из Git.

## Архитектура

```text
CLI         ──>  Application services  ──>  Domain model
      │                    │                      │
      └── CommandContext   └── Ports <── Infrastructure (JSON, PBKDF2)
```

- `core/model` — доменные объекты и инварианты: `Wallet`, `CategoryRegistry`, `TransactionLedger`, `BudgetBook`, `Money`.
- `core/service` — сценарии приложения: авторизация, операции, переводы, отчёты, уведомления, импорт/экспорт, демо.
- `core/port` — интерфейсы `UserRepository`, `WalletRepository`, `SnapshotCodec`, `PasswordHasher`.
- `infra` — JSON-хранилища, Jackson, PBKDF2.
- `cli` — разбор команд, консоль, таблицы, команды; бизнес-логики здесь нет.
- `bootstrap` — ручная сборка зависимостей.

Подробнее: [docs/architecture.md](docs/architecture.md).

## Тесты и качество

```bash
mvn test      # unit- и интеграционные тесты
mvn verify    # тесты + Checkstyle + отчёт JaCoCo
```

## Решения и ограничения

- Деньги хранятся в `BigDecimal` с двумя знаками после запятой; суммы не используют `double`.
- Названия категорий уникальны без учёта регистра; отображается написание, с которым категория была создана.
- Операция автоматически создаёт категорию нужного типа, а установка бюджета требует уже существующую расходную категорию — так пользователь явно планирует бюджет.
- Удалить можно только категорию без операций и бюджета; иначе данные истории были бы потеряны. Для исправления используйте переименование.
- Бюджет — это лимит на категорию, а не автоматически сбрасываемый месячный план. Период можно задать в отчётах.
- В одном процессе активна одна пользовательская сессия — это соответствует интерактивному CLI.
- Данные кошельков хранятся в JSON без шифрования; пароли защищены хешем. Для учебного локального приложения этого достаточно.
