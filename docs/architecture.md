# Архитектура Finance Wallet CLI

## Цели

Приложение решает три задачи:

1. хранить данные нескольких пользователей и их кошельков в памяти;
2. предоставлять бизнес-операции (доходы, расходы, бюджеты, переводы, отчёты);
3. сохранять и загружать состояние через JSON, не смешивая хранение с бизнес-логикой.

## Слои

```text
┌──────────────────────────────────────────────────────────────┐
│ cli                                                          │
│ Console, CommandLine, CommandRegistry, Table, команды,       │
│ OutputFormatter, AppSession                                  │
└──────────────────────────────┬───────────────────────────────┘
                               │ вызовы сервисов
┌──────────────────────────────▼───────────────────────────────┐
│ core.service                                                 │
│ AuthService, FinanceService, TransferService, ReportService, │
│ NotificationService, SnapshotService, DemoService            │
└───────────────┬──────────────────────────────┬───────────────┘
                │ доменные операции            │ порты
┌───────────────▼──────────────┐  ┌────────────▼───────────────┐
│ core.model                   │  │ core.port                  │
│ Wallet, CategoryRegistry,    │  │ UserRepository,            │
│ TransactionLedger,           │  │ WalletRepository,          │
│ BudgetBook, Money, records   │  │ SnapshotCodec,             │
└──────────────────────────────┘  │ PasswordHasher             │
                                  └────────────▲───────────────┘
                                               │ реализации
┌──────────────────────────────────────────────┴───────────────┐
│ infra                                                        │
│ JsonUserRepository, JsonWalletRepository, JsonSnapshotCodec, │
│ JsonMapperFactory, JsonFiles, Pbkdf2PasswordHasher           │
└──────────────────────────────────────────────────────────────┘
```

Зависимости направлены внутрь: `cli` и `infra` зависят от `core`, а `core` не знает о Jackson, файлах и консоли.

## Пакеты

### `core.model`

Доменная модель. Здесь находятся инварианты, которые нельзя обойти через CLI.

| Класс | Ответственность |
|---|---|
| `Wallet` | Агрегат кошелька: владелец, категории, операции, бюджеты; единая точка изменения |
| `CategoryRegistry` | Уникальность категорий без учёта регистра, тип категории, переименование |
| `TransactionLedger` | Неизменяемые операции, выборки, суммы по типам, категориям и периодам |
| `BudgetBook` | Лимиты только для расходных категорий, переименование вместе с категорией |
| `Money` | Разбор, нормализация до 2 знаков и форматирование сумм |
| `Transaction`, `Budget`, `Category` | Неизменяемые записи с проверкой значений |
| `BudgetStatus` | Потрачено, остаток, процент, состояние (`OK`, `WARNING`, `REACHED`, `EXCEEDED`) |
| `DateRange` | Полуинтервал `[from, to)` и преобразование календарных дат в `Instant` |

Ключевые инварианты:

- сумма операции и лимит бюджета строго положительны;
- операция ссылается на существующую категорию соответствующего типа;
- бюджет существует только для расходной категории;
- переименование категории обновляет операции и бюджет;
- удаление категории с историей или бюджетом запрещено;
- идентификаторы операций уникальны.

### `core.service`

Прикладные сценарии, которые комбинируют модель, порты и уведомления.

| Сервис | Ответственность |
|---|---|
| `AuthService` | Регистрация, проверка пароля, нормализация логина |
| `FinanceService` | Доходы, расходы, категории, бюджеты; сохранение после каждой мутации |
| `TransferService` | Атомарная пара операций между двумя кошельками |
| `ReportService` | Сводки, категории, бюджеты, фильтры по типу/категориям/периоду |
| `NotificationService` | Уведомления при пересечении порогов, а не при каждом вызове |
| `SnapshotService` | Экспорт/импорт снимка, `--force`, проверка владельца |
| `DemoService` | Пример из задания для пустого кошелька |

`FinanceService` не является God-классом: он не форматирует вывод, не читает консоль и не занимается JSON напрямую. Его задача — валидировать сценарий, вызвать модель, сохранить результат и собрать уведомления.

### `core.port`

Интерфейсы, отделяющие бизнес-логику от инфраструктуры:

- `UserRepository` — поиск и сохранение пользователей;
- `WalletRepository` — загрузка и сохранение кошелька по владельцу;
- `SnapshotCodec` — чтение/запись снимка;
- `PasswordHasher` — хеширование и проверка пароля.

Благодаря портам тесты могут использовать быстрый тестовый хешер, а инфраструктуру можно заменить, не меняя сервисы.

### `infra`

| Класс | Ответственность |
|---|---|
| `JsonUserRepository` | Индекс пользователей в памяти + `data/users.json` |
| `JsonWalletRepository` | Кеш кошельков + отдельный JSON на пользователя |
| `JsonSnapshotCodec` | Jackson-сериализация снимка |
| `WalletSnapshotMapper` | Преобразование домена в DTO и обратно; проверка схемы |
| `JsonFiles` | UTF-8 и атомарная запись через временный файл |
| `Pbkdf2PasswordHasher` | PBKDF2-HMAC-SHA256, 120 000 итераций, соль 128 бит |

Имена файлов кошельков кодируются Base64 URL, чтобы поддержать кириллические логины и избежать недопустимых символов в имени файла.

### `cli`

- `CommandLine` — токенизация с кавычками и сохранением Windows-путей;
- `CommandRegistry` — поиск команд, псевдонимы, подсказка по расстоянию Левенштейна;
- `Command` — контракт команды (имя, использование, примеры, нужна ли авторизация);
- `CommandContext` — зависимости, передаваемые командам;
- `AppSession` — текущий пользователь и загруженный кошелёк;
- `Console`, `Table`, `OutputFormatter` — только ввод-вывод и оформление;
- `cli.command.*` — разбор аргументов и вызов сервисов.

`CliApplication` читает команды в цикле, перехватывает ожидаемые ошибки, не завершает процесс из-за неверного ввода и гарантированно сохраняет кошелёк при `exit`/EOF.

### `bootstrap`

`ApplicationFactory` вручную собирает граф зависимостей. Это позволяет тестировать CLI с `StringReader`/`PrintWriter` и временной папкой данных без запуска отдельного процесса.

## Поток операции расхода

```text
CLI expense
  → Message parse (Money, note)
  → FinanceService.addExpense
      → запомнить состояние «до»: потрачено по категории, расходы, баланс
      → Wallet.addExpense
          → CategoryRegistry.ensure (создать категорию при необходимости)
          → TransactionLedger.add (проверить сумму и уникальность id)
      → WalletRepository.save (JSON атомарно)
      → NotificationService.afterExpense
          → сравнить пороги «до/после»
  → Console: результат + уведомления
```

## Поток сохранения/загрузки

```text
login:
  JsonWalletRepository.findByOwner
    → кеш в памяти?
    → иначе прочитать data/wallets/<base64>.json
    → WalletSnapshotMapper.fromSnapshot
    → проверить схему, владельца, категории, операции, бюджеты
    → Wallet.restore

изменение:
  сервис → WalletRepository.save
    → WalletSnapshotMapper.toSnapshot
    → JsonSnapshotCodec.write
    → JsonFiles: временный файл → атомарный rename

exit / logout:
  FinanceService.save ещё раз; даже если операция уже сохранена, это безопасно
```

## Обработка ошибок

- `ValidationException` — неверный пользовательский ввод (сумма, логин, дата, параметр).
- `DomainException` — нарушено бизнес-правило (дубликат, тип категории, недостаточно средств, удаление используемой категории).
- `PersistenceException` — ошибка чтения/записи/формата JSON.
- `CommandException` — синтаксис CLI.

`CliApplication` показывает сообщение и продолжает цикл. Неожиданные `RuntimeException` также не роняют приложение, но помечаются как внутренняя ошибка.

## Тестовая стратегия

- Unit-тесты модели и утилит: деньги, кавычки, периоды, бюджеты.
- Service-тесты: авторизация, операции, пороги уведомлений, переводы, отчёты, импорт/экспорт.
- Integration-тесты CLI: полный сценарий задания, авторизация, сохранение между запусками, переводы, экспорт/импорт, EOF.
- `mvn verify` дополнительно запускает Checkstyle и JaCoCo.

## Возможные расширения

- Месячные бюджеты с автоматическим сбросом и историей периодов.
- REST API поверх тех же сервисов (порты уже отделяют хранение).
- Шифрование файлов кошельков.
- Подключение СУБД вместо JSON-репозитория.
- Цветной вывод и интерактивный пошаговый мастер.
